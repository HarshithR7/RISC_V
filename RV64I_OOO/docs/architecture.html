System architecture — coherent dual-core

Two independent OoO cores (each 2-thread SMT) hold private write-back L1s; l2_cache.v arbitrates a shared, inclusive L2 as a real MESI director across three coherent ports — core 0, core 1, and a reserved GPU-class port that speaks the identical req/resp+snoop protocol but has no compute core wired to it yet. An AXI4-Lite peripheral lets an external host load programs and start/stop the cores without re-synthesizing.

Alternate configuration — lockstep DMR

For redundancy instead of throughput, two full core copies run the identical program from identical initial state with no coherence link between them at all — every signal that would join them in Fig. 1 is absent by construction. A comparator watches both every cycle and latches a sticky fault flag on any divergence.

Core microarchitecture — 3-wide OoO pipeline

One thread's slice through a single core. Fetch is speculative (icache + BTB + RAS + BHT); dispatch renames through the RAT and allocates a ROB tag and a reservation-station entry in the same cycle; execution is free-running out of order; three common data buses arbitrate oldest-ROB-tag-first and are the one resource every bank contends for; commit is strictly in order and is the only place architectural state — register file, memory, RAT — is ever actually written.

program data / control common data bus + misprediction path side-band (alloc / commit-clear)

What the CDB diagram hides on purpose

  • Age is tag − rob_head_tag under unsigned wraparound, not raw tag magnitude — the head, if requesting, always wins.
  • A resolved branch and a ready store never touch the CDB — they use rob.v's unarbitrated mark2 / extra_mark ports instead, since neither has a value to broadcast.
  • SMT doubles most of this figure per-thread (front end, ROB, RAT, branch_rs); the RS banks, LSQ and CDB are shared and tag every entry with tid.

What Fig. 1 leaves out on purpose

  • SECDED ECC on the register file, L1, L2 and ROB payload — a correctness layer orthogonal to the dataflow shown here.
  • Hardware next-line prefetch, hit-under-miss, and the merging write buffer inside l1_cache.v.
  • The RVV vector datapath (vec_rs.v / vec_rat.v), thread-0-only, broadcasting on its own dedicated ROB port.
